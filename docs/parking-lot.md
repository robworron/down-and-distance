# Parking lot

Ideas for later. Not part of the current step.

- **npm audit: 5 high-severity findings in the lint toolchain (2026-10-17).** All sit under `eslint-config-next` 16.4.1 (`@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces`, advisory GHSA-vfj7-8cjw-p6xm, a denial of service via deeply nested glob patterns). They are dev-only: `npm audit --omit=dev` finds 0 vulnerabilities, so nothing ships to the site. npm's only fix is downgrading `eslint-config-next` to 14.x, which would break linting. Recheck when Next publishes a patched `eslint-config-next`, at the latest in Phase 7.
- **Phase 4: league views show win % only for team-level situations (2026-10-17).** In a game-level situation (`level = 'game'` in `marts.situations`: weather, roof, surface, time slot, primetime, opponent type) both teams share the value, so the league's win % is 50% by construction. League views of those should show scoring and over/under rate instead. The same goes for venue's `neutral` value.
- **Phase 4: value labels and display order for the registry (2026-10-17).** `situations.csv` stores values like `32_or_below` in display order, but no human labels ("32°F or below"), and no order for the situations themselves. Add them (e.g. a `value_labels` column and a `sort_order`) when the filters are built in 4.5/4.7.
- **Phase 5: check documentation coverage in CI (2026-10-17).** Step 2.12 described all 391 columns and checked it with a one-off script comparing `transform/target/manifest.json` with `information_schema`. A pull-request check that fails when a new model or column has no description would keep it that way.
